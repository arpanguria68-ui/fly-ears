# fly-ears: does a real fly brain hear the difference between human and AI music?

Songs are played into the ears of the complete fruit fly connectome (MaleCNS: 166,700 neurons,
25.6 M connections, simulated by `flybrain` from [fly.ai](https://github.com/alextitonis/fly.ai)),
and its responses are recorded. Then one question: can you tell from **how the brain
responds** whether a song was made by people or generated by AI, and does the brain add anything
beyond what its ears received?

A separate project: it imports `flybrain` and trains nothing inside the brain. The connectome is
frozen; only a plain logistic readout is fitted, on training songs only.

## How a song reaches the brain

```
audio file ──ffmpeg──> mono, 8 kHz ──> clips (fixed positions) ──> same loudness
   └─> 8 frequency bands, 80 Hz - 1.2 kHz (the fly hears low; most music detail is above)
         └─> loudness per band every 20 ms ──> voltage into Johnston's organ neurons
               (JO-B: low bands, JO-A: high bands; 138 sound-sensing neurons)
                 └─> 0.5 s of silence to settle, then the clip, through the whole connectome
                       └─> spike rates of fixed groups: the ear, AMMC, WED/WEDPN (auditory relay),
                           and every superclass (descending neurons, motor, ...), every 20 ms
```

## Questions, decided before running

1. **Reference:** plain full-band audio features separate human from AI (if not, the set is too hard).
2. **The fly hears it:** the brain's responses separate the classes above chance (permutation p < 0.05).
3. **The brain adds something:** the brain's responses beat *its own ear input*, summarised the same
   way (paired bootstrap 95% CI of the AUC difference above 0). If not, the brain only passes on what
   its ears got: an honest negative.
4. **The wiring matters:** the real connectome beats a degree-preserving rewired copy.

The ablation "flat ear" (every ear neuron hears all bands alike) tests the tonotopic assumption.

## Keeping it unbiased

| risk | what is done |
|---|---|
| file format / bitrate gives the class away | every file decoded the same way; `--same-codec` first pushes all through one MP3 codec |
| AI masters are louder | every clip set to the same loudness |
| choosing "good" parts | clips at fixed positions (1/4, 1/2, 3/4 of the song), never by content |
| clips of one song in training and test | splits by **song**; a song's score is the mean over its clips; statistics count songs |
| unequal classes | the larger class is randomly cut to the size of the smaller (seeded, reported) |
| tuning on the test set | fixed readout (L2 logistic, fixed strength), standardised on training songs only |
| chance looking like a result | label-permutation null (whole cross-validation rerun), bootstrap CIs over songs |
| the method itself leaking | `--synthetic`: a null set (both classes from one generator) must score ~0.5 everywhere |
| many groups compared | per-group differences Holm-corrected |

What it can't remove: if your human and AI folders differ in genre, era or production style,
that difference is what gets detected. Match them as well as you can (same genres, similar
tempos, the AI songs prompted to resemble the human ones).

## Use it

Needs the fly.ai code next to this folder (`../firefly`, or set `FLYBRAIN_SRC`) and its Python
environment (NumPy, SciPy; CuPy for the GPU), plus `ffmpeg` on the PATH.

```powershell
# 1. check the method (no songs needed, ~5 min on a GPU)
..\firefly\.venv\Scripts\python.exe run.py --synthetic

# 2. your songs: songs\human\*.mp3 and songs\ai\*.mp3 (at least 4 each; 20+ each for real conclusions)
..\firefly\.venv\Scripts\python.exe run.py songs --same-codec

# a quick first look (real brain only, fewer permutations)
..\firefly\.venv\Scripts\python.exe run.py songs --quick
```

Results: `out/<folder>/report.md` (tables, the four answers, how each neuron group responds) and
`results.json`. Brain responses are cached, so re-running the statistics is fast.

Tests (no brain, GPU or audio needed): `python -m pytest tests -q`.

## Method check (synthetic songs, 12 per class, real GPU run)

| feature set | **null** set: AUC (p) | **signal** set: AUC (p) |
|---|---|---|
| audio (full band) | 0.58 (0.37) | **0.94 (0.005)** |
| ear input | 0.46 (0.57) | 0.79 (0.050) |
| brain (real) | 0.57 (0.32) | 0.44 (0.68) |
| brain (rewired) | 0.52 (0.45) | 0.53 (0.44) |
| brain (flat ear) | 0.58 (0.33) | 0.74 (0.085) |

* **No leak:** on the null set (both classes from one generator) nothing beats chance.
* **The pipeline finds a real difference:** on the signal set (machine-tight vs played timing),
  plain audio finds it clearly and the ear input mostly does.
* **The brain, as wired here, does not pass it on.** The ear neurons respond strongly to sound
  (0.28 -> 12.3 spikes/s), but the auditory relay barely changes (WED 2.66 -> 2.83, WEDPN
  5.55 -> 5.69 spikes/s; AMMC slightly down), so the timing difference drowns in the brain's own
  background activity. This is a result about this model, not a bug, and the ear strength was
  NOT turned up to make the brain "work": that would be tuning on the answer. Any change to the
  ear gain should be decided without labels (for example: set it so the relay's response to
  sound, averaged over all songs, reaches a target), written down, then rerun.

## Files

| file | what it does |
|---|---|
| `flyears/audio.py` | decode, fixed clips, loudness |
| `flyears/ear.py` | frequency bands -> Johnston's organ neurons |
| `flyears/listen.py` | play clips to the connectome (real or rewired), record group rates |
| `flyears/features.py` | the same summary for ear input and brain output; full-band audio baseline |
| `flyears/evaluate.py` | song-level cross-validation, permutation null, bootstrap |
| `flyears/synth.py` | synthetic null and signal sets |
| `run.py` | everything, and the report |

Your audio files stay on your PC: `songs/` is ignored by git, and nothing is uploaded.
